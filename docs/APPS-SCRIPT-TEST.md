# 앱스크립트 제출 시험 (프로토타입)

구글 폼 대신 **앱스크립트 웹앱 + 구글 시트**로 제출을 받을 수 있는지 확인하는 시험입니다.
기존 학생 흐름(앱, 폼 4개, 갤러리)은 그대로이고, 이 시험은 따로 떨어져 있습니다.

| 파일 | 하는 일 |
|---|---|
| `apps-script/Code.gs` | 웹앱 서버. 학번 등록·비밀번호 확인, HTML 저장 |
| `site/lab/index.html` | 시험 페이지. 연결 확인, 등록·로그인, 제출, 이력, 진단, 부하 시험 |
| `site/lab/privacy.html` | 개인정보 처리 안내 |
| `tests/test_apps_script.js` | 서버 로직 단위 테스트 (`node tests/test_apps_script.js`) |

## 본인 확인 방식: 학생이 정한 비밀번호

처음에는 구글 로그인으로 본인을 확인하려 했지만, **학생 크롬북에서는 학교(교육청) 관리자 설정 때문에 막혔습니다**(`오류 400: access_not_configured`, 2026-11-20 확인). 그래서 지금은 아래 방식을 씁니다.

1. 학생이 처음에 **학번·이름·비밀번호**를 등록합니다.
   - **명단 없이 시작**(Config `roster_required`=`FALSE`, 기본값): 처음 등록할 때 `Roster`에 학번·이름이 자동으로 추가됩니다(3열 `추가`에 `자동`). 그 뒤 같은 학번은 다시 등록할 수 없습니다.
   - **명단으로 시작**(`roster_required`=`TRUE`): 선생님이 `Roster`에 넣어 둔 학번만, 그 이름과 똑같이 써야 등록됩니다.
   - 어느 쪽이든 `Roster`에 이름이 이미 있는 학번은 그 이름과 같아야 합니다.
2. 제출할 때마다 학번과 비밀번호를 넣습니다. 맞아야 제출이 쌓입니다(덮어쓰지 않음).
3. **비밀번호를 잊어버리거나 잠기면** 선생님이 **관리자 화면**(아래 2-1)에서 그 학생을 찾아 [초기화]를 누릅니다(시트 `Accounts` 탭의 `초기화` 칸에 `Y`를 직접 써도 같습니다). 그러면 **비밀번호가 학번**이 되고, 잠금도 풀립니다. 학생이 학번으로 로그인하면 **새 비밀번호를 정하는 창**이 나오고, 새 비밀번호를 정해야 들어갈 수 있습니다(학번 그대로는 안 됨). 정하면 초기화 표시(`Y`)는 저절로 지워집니다. 예전 비밀번호와 그전에 로그인해 둔 화면은 더 이상 쓸 수 없습니다. `초기화시각` 칸은 자동으로 채워집니다.
   - `Y`가 있는 동안은 학번으로만 로그인할 수 있고, 로그인하면 바로 새 비밀번호를 정합니다.
4. 같은 학번으로 5번 틀리면 그 학번은 5분 동안 잠깁니다. 기다리기 어려우면 위처럼 초기화하세요.
5. 비밀번호 규칙은 없습니다(빈칸만 아니면 됨). 학생들이 기억하기 쉽게 하려고 일부러 두지 않았습니다.
6. 로그인하면 페이지는 비밀번호 대신 임시 로그인 표(세션)만 들고 있다가 제출 때 씁니다. 6시간 뒤나 비밀번호를 바꾸면 끝나고, 그때는 다시 로그인합니다.

- 비밀번호는 시트에 그대로 저장하지 않고 암호화(해시)해서 저장합니다. 선생님도 원래 비밀번호는 볼 수 없습니다.
- 학생에게 "구글 비밀번호를 쓰지 말고 새로 정한 비밀번호를 쓰라"고 꼭 안내하세요.
- **약점**: 친구의 학번과 이름을 아는 학생이 먼저 등록할 수 있습니다. 그래서 1차시 시작할 때 **다 같이 5분 안에 등록**하게 하세요. 본인이 "이미 등록된 학번"을 보면 선생님께 말하고, 선생님이 `Accounts`에서 그 행을 지우면 다시 등록할 수 있습니다. 지운다고 제출물이 지워지지는 않습니다. 명단 없이 시작하면 이름 확인도 없으므로, 학번을 잘못 쳐서 남의 학번으로 등록되는 일도 생길 수 있습니다. 이때도 `Accounts`와 `Roster`(3열이 `자동`인 행)에서 그 학번 행을 지우면 처음부터 다시 등록할 수 있습니다.
- **약점 2**: 친구 학번으로 일부러 5번 틀려 5분 동안 잠그게 할 수 있습니다. 반복되면 그 시간 동안 기다리거나 선생님이 상황을 확인하세요.
- **약점 3**: 초기화한 뒤 본인이 새 비밀번호를 정하기 전에는, 학번을 아는 친구가 먼저 로그인해 비밀번호를 정해 버릴 수 있습니다. 초기화는 그 학생이 바로 로그인할 수 있을 때 하세요.
- **약점 4**: 비밀번호 규칙이 없어서 1234처럼 쉬운 비밀번호도 됩니다. 친구가 맞힐 수 있으니 "남이 쉽게 맞히지 못할 것"으로 정하라고 말로 안내하세요.
- 더 단단하게 하려면 선생님이 학생마다 **등록 코드**를 쪽지로 나눠 주는 방식으로 바꿀 수 있습니다(본 구현 때 결정).
- 구글 로그인 방식 코드는 지우지 않았습니다. 관리자가 허용해 주면 Config `auth_mode`를 `google`로 바꿔 쓸 수 있습니다(맨 아래 부록).

## 1. 구글 시트 + 앱스크립트

1. 내 드라이브에서 **새 구글 시트** → 이름 `vibe-lab 제출 시험`.
2. 시트 메뉴 **확장 프로그램 → Apps Script**.
3. 왼쪽 `Code.gs` 내용을 모두 지우고, 저장소의 `apps-script/Code.gs` 내용을 통째로 붙여넣기 → 저장(Ctrl+S).
4. 편집기 위쪽 함수 선택에서 **`setup`** 을 고르고 **실행**.
   - 권한 승인 창: 계정 선택 → "Google에서 확인하지 않은 앱" → **고급 → (안전하지 않음)으로 이동** → 허용.
   - 시트에 `Roster`, `Accounts`, `Submissions`, `Config` 탭(구글 방식용 `Bindings`도)이 생기고, 드라이브에 `vibe-test-submissions` 폴더가 생깁니다.
   - 비밀번호 암호화에 쓰는 비밀 값(`PASSWORD_PEPPER`)이 스크립트 속성에 자동으로 만들어집니다. **지우거나 바꾸면 모든 학생이 다시 등록해야 합니다.**
5. **Roster** 탭은 비워 둬도 됩니다(학생이 등록할 때 자동으로 채워짐). 명단을 미리 쓰고 싶으면 `roster_required`를 `TRUE`로 두고 학번·이름을 넣습니다. 이때 이름이 비어 있는 학번은 등록되지 않습니다.
6. **Config** 탭 값

| 키 | 값 | 뜻 |
|---|---|---|
| `auth_mode` | `password` | 본인 확인 방식. `google`은 부록 참고 |
| `roster_required` | `FALSE` | `FALSE`: 명단 없이 시작, 처음 등록할 때 Roster에 자동 추가. `TRUE`: Roster에 있는 학번만 등록 |
| `max_html_bytes` | `2097152` | 제출 크기 상한(2MB). 실제 공개 상한은 1MB이므로 1MB~2MB 파일은 `ingest.py`에서 '실패'로 나옵니다 |
| `session_open` | `TRUE` | `FALSE`면 제출을 막음(`SESSION_CLOSED`) |
| `submit_per_minute` | `5` | 한 학번이 1분에 낼 수 있는 제출 수. 넘으면 `BUSY`. 제출 부하 시험(T11) 때만 `50`으로 올렸다가 돌려놓기 |
| `allowed_domains`, `allow_personal` | | 구글 방식에서만 씀 |

> 이미 있는 시트에 코드를 새로 붙였다면 `setup`을 한 번 더 실행하세요. 없는 탭·키만 추가됩니다.

## 2. 웹앱 배포

1. 편집기 오른쪽 위 **배포 → 새 배포** → 톱니바퀴(유형 선택) → **웹 앱**.
2. 설명 `lab-1`, **실행 사용자: 나**, **액세스 권한: 모든 사용자** → 배포.
3. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
4. 브라우저 새 탭에 그 주소를 열어 `{"ok":true,…}`가 보이면 성공입니다.

> **코드를 고친 뒤에는 반드시** **배포 → 배포 관리 → (연필) 수정 → 버전: 새 버전 → 배포**로 올리세요.
> **새 배포**를 다시 누르면 주소가 바뀌어 시험 페이지의 주소도 바꿔야 합니다.
> 저장만 하고 새 버전으로 올리지 않으면 웹앱은 옛 코드를 계속 씁니다.

## 2-1. 선생님 관리자 화면

**주소는 이 문서(공개 저장소)에 적지 않습니다.** 학생 눈에 띄지 않도록 선생님들만 아는 곳(개인 북마크, `private/admin-url.txt`)에 둡니다. 형식은 웹앱 주소 끝에 `?admin=<주소 열쇠>`를 붙인 것입니다.

**처음 한 번 설정** (스크립트 편집기 → 왼쪽 톱니바퀴 "프로젝트 설정" → 맨 아래 "스크립트 속성" → 속성 추가):

| 속성 | 값 | 뜻 |
|---|---|---|
| `ADMIN_KEY` | 길고 아무렇게나 만든 글자(예: 영문·숫자 20자 이상) | 주소 열쇠. 이 값이 틀린 주소는 관리자 화면이 아니라 평소 응답(`{"ok":true,…}`)만 보여 줍니다 |
| `ADMIN_PASSWORD` | 선생님들이 함께 쓸 비밀번호 | 개인 계정 등 같은 학교 계정이 아닌 선생님이 들어갈 때 씁니다. **비워 두면 같은 학교 계정만** 들어갑니다 |
| `ADMIN_EMAILS` | 같은 학교 선생님 이메일(쉼표로 구분) | 이 계정으로 로그인한 선생님은 비밀번호 없이 들어갑니다(선택) |

`ADMIN_KEY`를 설정하기 전에는 열쇠가 `1`이라 `?admin=1`로 열립니다. 설정한 뒤에는 `?admin=1`이 막힙니다.

**쓰는 법**
- 같은 학교 계정(배포한 선생님 또는 `ADMIN_EMAILS`)은 바로 열립니다. 여러 구글 계정에 로그인된 Chrome에서는 주소의 `/macros/` 앞에 `/a/학교도메인`이 들어간 주소로 여세요.
- 그 밖의 선생님(개인 계정 등)은 화면에 나오는 **관리자 비밀번호** 칸에 `ADMIN_PASSWORD`를 넣습니다. 여러 선생님이 함께 쓰므로 틀려도 잠기지 않습니다(주소 열쇠를 알아야 비밀번호 칸이 나옵니다).
- 등록한 학생 목록이 학번 순으로 나옵니다: 학번, 이름, 등록 시각, 제출 수, 최근 제출, 상태(정상 / 잠김 / 초기화됨). **학번 일부나 이름**을 넣고 [조회]를 누르면 찾습니다.
- [초기화]를 누르고 확인하면 그 학생의 비밀번호가 학번이 되고 잠금이 풀립니다. 학생은 학번으로 로그인한 뒤 새 비밀번호를 정합니다. 그 학생이 지금 로그인해 둔 화면은 끊깁니다.
- **갤러리용 내려받기**: 반을 고르고 [이 반 내려받기]를 누르면 그 반 학생들이 **가장 최근에 낸 작품**만 담긴 zip이 내려받아집니다. [모든 반 차례로 내려받기]는 반마다 zip을 하나씩 받습니다. 받은 zip은 풀지 않고 그대로 `python tools/ingest.py 받은.zip`에 넣으면 됩니다(README의 수집·공개 순서와 같음).
- **글·투표** (학생 앱에서 직접 제출한 것):
  - 학생 목록: 학생마다 1차시 기획서·게임·2~3차시 기록·투표·4차시 소감을 냈는지(✓와 마지막 시각)가 먼저 보이고, [자세히]를 누르면 글 내용, 게임 제출 횟수, 투표한 번호, 그 학생의 작품 번호가 창으로 나옵니다.
  - [글 내려받기 (CSV)]: 학생 한 명이 한 줄이고, 1차시 기획서·2~3차시 기록·4차시 소감(각각 가장 나중 것)과 제출 시각이 옆으로 나란히 들어갑니다. 등록했지만 안 낸 학생은 빈칸입니다. 열 이름에 `학번`이 있어 `ingest.py --form1`에 그대로 쓸 수 있습니다(서약 확인).
  - [투표 집계 보기]: 반마다 투표한 학생 수와 많이 받은 작품 번호 1~5위(표 수).
  - [투표 내려받기 (CSV)]: 학번·반·번호. `python tools/tally.py votes.csv`로도 반별 순위를 볼 수 있습니다.
  - **작품 번호 명단**: 갤러리를 공개한 뒤 `private/mapping.csv` 내용을 그대로 붙여넣고 [명단 올리기]. 서버는 공개(Y)한 작품의 학번·반·번호만 Gallery 탭에 저장합니다. **이 명단이 있어야 학생이 투표할 수 있고**, 학생이 자기 작품 번호나 우리 반에 없는 번호를 고르면 막힙니다.
  - 투표를 닫으려면 시트 Config 탭의 `vote_open`을 `FALSE`로 바꿉니다(없으면 열려 있음).
- 같은 학교 계정으로 처음 열 때 한 번 "이메일 주소 보기" 권한 승인이 필요합니다(편집기에서 함수를 한 번 실행하면 나옴).
- 관리자 화면은 시트를 직접 읽고 쓰므로, 시트에서 직접 고친 내용도 그대로 보입니다.
- 다른 선생님께는 **관리자 주소와 비밀번호만** 따로 전해 주세요. 구글 시트나 스크립트를 공유하면 학생 정보와 코드가 모두 보이고 고칠 수도 있습니다.

## 3. 시험 페이지 설정과 열기

1. `site/lab/index.html`의 `CONFIG`에서 `WEB_APP_URL`을 2-3의 주소로, `AUTH_MODE`를 `'password'`로 둡니다.
2. **로컬에서 먼저 시험**: 저장소 폴더에서 아래 명령을 실행하고 http://localhost:8000/lab/ 을 엽니다.

```powershell
python -m http.server 8000 --directory site
```

3. **Pages 주소에서 시험(학생 크롬북용)**: `main`에 push되면 https://176-oss-gallery.github.io/vibe-coding-class/lab/ 에 올라갑니다.
   - 시험 페이지에는 학생 정보가 없고 검색 제외(noindex)로 되어 있지만, 주소를 아는 사람은 누구나 열 수 있습니다.
   - 시험이 끝나면 `site/lab/` 폴더를 지우고 push하세요(아래 6절).

## 5. 수업 때 학생 안내 (예시)

> 1. 선생님이 알려 준 주소를 엽니다.
> 2. [처음이에요: 등록]에서 학번, 이름, **새로 정한 비밀번호**를 넣습니다. 구글 비밀번호를 쓰지 마세요.
> 3. 비밀번호를 잊어버리거나 잠기면 선생님께 말하세요. 선생님이 초기화하면 **학번**으로 로그인합니다.
> 4. "이미 등록된 학번"이 나오면 바로 선생님께 말하세요.

## 6. 시험이 끝나면

- `site/lab/` 폴더를 지우고 push → Pages에서 내려갑니다.
- 웹앱: **배포 → 배포 관리 → 보관처리**(archive)로 주소를 끕니다.
- 시트의 `Accounts`, `Bindings`, `Submissions`는 공유하지 말고, 시험 뒤 지웁니다.

## 기존 설계와 달라지는 점 (본 구현 때 반영할 것)

- 본인 확인을 구글 폼의 "로그인 이메일 확인" 대신 **학생이 정한 비밀번호**로 합니다. 구글이 신원을 보증하지 않으므로 먼저 등록하기 문제가 있고, 수업 운영(동시 등록, 초기화)으로 보완합니다.
- 제출 표식(`vibe-submit`)을 학생 브라우저가 아니라 **서버가** 붙입니다. 학생이 붙여넣은 HTML 맨 앞의 `vibe-submit` 줄은 지우고, 등록된 학번·이름으로 새로 씁니다. `vibe-info` 줄은 그대로 둡니다.
- 이름의 `>`, `--`도 지웁니다(`tools/common.py`의 표식 정규식, HTML 주석 규칙).
- 제출할 때 드라이브 파일 저장은 "한 명씩" 잠금 밖에서 하고, 잠금 안에서는 버전 번호와 기록만 합니다(동시 제출이 몰릴 때 대기 시간을 줄이기 위해). 파일은 먼저 `학번_시각_해시.html`로 저장된 뒤 `학번_v버전_시각.html`로 이름이 바뀝니다.
- Submissions 시트는 잠금을 잡은 뒤에만 읽습니다. 앱스크립트는 한 실행 안에서 같은 범위를 다시 읽을 때 처음 값을 돌려줄 수 있어서, 잠금 밖에서 먼저 읽으면 버전 번호가 겹칩니다(2026-11-20 부하 시험에서 실제로 발생).
- 처음 사양의 "HtmlService 금지"는 학생 화면에만 지킵니다. 선생님 관리자 화면만 HtmlService로 만들었고, 학생 HTML은 어디에서도 실행하거나 보여 주지 않습니다.
- 제출 크기 상한 기본값이 2MB라서 SPEC의 1MB 상한과 다릅니다. 본 구현 때 1MB로 맞출지 정해야 합니다.
