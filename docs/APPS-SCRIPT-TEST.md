# 앱스크립트 제출 시험 (프로토타입)

구글 폼 대신 **앱스크립트 웹앱 + 구글 시트**로 제출을 받을 수 있는지 확인하는 시험입니다.
기존 학생 흐름(앱, 폼 4개, 갤러리)은 그대로이고, 이 시험은 따로 떨어져 있습니다.

| 파일 | 하는 일 |
|---|---|
| `apps-script/Code.gs` | 웹앱 서버. 구글 로그인 확인, 학번 연결, HTML 저장 |
| `site/lab/index.html` | 시험 페이지. 연결 확인, 로그인, 학번 연결, 제출, 이력, 진단, 부하 시험 |
| `tests/test_apps_script.js` | 서버 로직 단위 테스트 (`node tests/test_apps_script.js`) |

이번 시험에서 **확인할 것은 세 가지**입니다.
1. 학생 크롬북에서 웹앱 주소로 전송이 되는가
2. 학생 계정으로 구글 로그인이 되는가 (학교 관리자가 막았는지)
3. 30명이 한꺼번에 보내도 버티는가

---

## 1. 구글 클라우드: 로그인용 클라이언트 ID 만들기 (선생님 계정, 약 10분)

1. https://console.cloud.google.com 접속 → 위쪽 프로젝트 선택 → **새 프로젝트** → 이름 `vibe-lab` → 만들기.
2. 왼쪽 메뉴 **API 및 서비스 → OAuth 동의 화면**(또는 **Google 인증 플랫폼 → 브랜딩**) → 시작하기.
   - 앱 이름: `바이브코딩 제출 시험`, 지원 이메일: 선생님 메일.
   - 대상(사용자 유형): **외부**.
   - 범위(데이터 액세스): 아무것도 추가하지 않습니다. 기본 `openid`, `email`, `profile`만 씁니다.
   - 앱 도메인: 홈페이지 `https://176-oss-gallery.github.io/vibe-coding-class/`, 개인정보처리방침 `https://176-oss-gallery.github.io/vibe-coding-class/lab/privacy.html`, 승인된 도메인 `176-oss-gallery.github.io`. 이 칸을 채워야 '앱 게시' 버튼이 켜집니다.
3. **대상(Audience)** 화면 → 게시 상태 **앱 게시(프로덕션으로 푸시)**.
   - 테스트 상태로 두면 등록한 사용자 100명까지만 로그인됩니다.
   - 기본 범위만 쓰므로 구글 심사(인증)는 필요 없습니다.
4. **클라이언트(사용자 인증 정보) → 클라이언트 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션**
   - **승인된 JavaScript 원본**에 세 줄을 넣습니다 (뒤에 `/`나 경로를 붙이지 않음):
     - `https://176-oss-gallery.github.io`
     - `http://localhost`
     - `http://localhost:8000`
   - 승인된 리디렉션 URI는 비워 둡니다.
5. 만들어진 **클라이언트 ID**(`…apps.googleusercontent.com`)를 복사해 둡니다. 비밀번호가 아니라서 공개돼도 됩니다. **클라이언트 보안 비밀번호(secret)는 쓰지 않으니 어디에도 붙이지 마세요.**

## 2. 구글 시트 + 앱스크립트

1. 내 드라이브에서 **새 구글 시트** → 이름 `vibe-lab 제출 시험`.
2. 시트 메뉴 **확장 프로그램 → Apps Script**.
3. 왼쪽 `Code.gs` 내용을 모두 지우고, 저장소의 `apps-script/Code.gs` 내용을 통째로 붙여넣기 → 저장(Ctrl+S).
4. 왼쪽 톱니바퀴 **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**
   - 속성 `GOOGLE_CLIENT_ID`, 값: 1-5에서 복사한 클라이언트 ID → 저장.
5. 편집기 위쪽 함수 선택에서 **`setup`** 을 고르고 **실행**.
   - 권한 승인 창: 계정 선택 → "Google에서 확인하지 않은 앱" → **고급 → (안전하지 않음)으로 이동** → 허용.
   - 시트에 `Roster`, `Bindings`, `Submissions`, `Config` 탭이 생기고, 드라이브에 `vibe-test-submissions` 폴더가 생깁니다.
6. **Roster** 탭에 시험할 학번·이름을 넣습니다 (학번 칸은 텍스트 형식). 선생님 시험용 학번도 하나 넣으세요 (예: `31640 시험용`).
7. **Config** 탭 값

| 키 | 값 | 뜻 |
|---|---|---|
| `roster_required` | `TRUE` | Roster에 없는 학번은 연결 거부 |
| `allowed_domains` | (비움) 또는 `학교도메인.kr` | 비우면 모든 구글 계정 허용. 학교 도메인을 넣으면 그 학교 구글 워크스페이스 계정만 허용 (개인 gmail은 거부) |
| `max_html_bytes` | `2097152` | 제출 크기 상한 (2MB). 실제 공개 상한은 1MB이므로 1MB~2MB 파일은 `ingest.py`에서 '실패'로 나옵니다 |
| `session_open` | `TRUE` | `FALSE`면 제출을 막음 (`SESSION_CLOSED`) |
| `submit_per_minute` | `5` | 한 계정이 1분에 낼 수 있는 제출 수. 넘으면 `BUSY`. 제출 부하 시험(T11) 때만 `50`으로 올렸다가 돌려놓기 |

> Config 탭이 이미 있는 시트에서 코드를 새로 붙였다면 `setup`을 한 번 더 실행하세요. 없는 키만 추가됩니다.

> 처음에는 `allowed_domains`를 비워 두고 선생님 개인 계정으로도 시험한 뒤, **학생 시험 전에는 반드시 학교 도메인을 넣으세요.** 비워 두면 아무 구글 계정이나 이름만 맞춰 남의 학번을 먼저 연결할 수 있습니다.
>
> **Bindings 탭의 `이름불일치`가 `Y`인 행**은 입력한 이름과 구글 계정 이름이 다르거나 Roster 이름과 다른 경우입니다. 이번 시험에서는 연결을 막지 않고 표시만 하니, 선생님이 확인하고 이상하면 그 행을 지우세요(지우면 다시 연결할 수 있습니다).
>
> 한 계정이 1분에 여러 번 제출하면 잠시 `BUSY`로 막힙니다(과부하 방지).

## 3. 웹앱 배포

1. 편집기 오른쪽 위 **배포 → 새 배포** → 톱니바퀴(유형 선택) → **웹 앱**.
2. 설명 `lab-1`, **실행 사용자: 나**, **액세스 권한: 누구나** → 배포.
3. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
4. 브라우저 새 탭에 그 주소를 열어 `{"ok":true,…}`가 보이면 성공입니다.

> **코드를 고친 뒤에는 반드시** **배포 → 배포 관리 → (연필) 수정 → 버전: 새 버전 → 배포**로 올리세요.
> **새 배포**를 다시 누르면 주소가 바뀌어 시험 페이지의 주소도 바꿔야 합니다.
> 저장만 하고 새 버전으로 올리지 않으면 웹앱은 옛 코드를 계속 씁니다.

## 4. 시험 페이지 설정과 열기

1. `site/lab/index.html` 맨 아래쪽 `<script>` 안의 `CONFIG`에 값 두 개를 채웁니다.
   - `GOOGLE_CLIENT_ID`: 1-5의 클라이언트 ID
   - `WEB_APP_URL`: 3-3의 웹 앱 URL
2. **로컬에서 먼저 시험**: 저장소 폴더에서 아래 명령을 실행하고 http://localhost:8000/lab/ 을 엽니다.

```powershell
python -m http.server 8000 --directory site
```

3. **Pages 주소에서 시험(학생 크롬북용)**: 배포 워크플로우는 `main`에 push될 때만 돕니다. 이 PR을 병합하면 https://176-oss-gallery.github.io/vibe-coding-class/lab/ 에 올라갑니다.
   - 시험 페이지에는 학생 정보가 없고 검색 제외(noindex)로 되어 있지만, 주소를 아는 사람은 누구나 열 수 있습니다.
   - 시험이 끝나면 `site/lab/` 폴더를 지우고 push하세요 (아래 7절).

## 5. 시험 체크리스트

시험 페이지의 **[진단 결과 복사]** 로 나온 글을 실제 결과 칸에 붙이면 됩니다.

| 번호 | 상황 | 기대 결과 | 실제 결과 |
|---|---|---|---|
| T1 | Pages 주소의 시험 페이지에서 1단계 [연결 확인] | 성공, 서버 시각 표시 (CORS 통과) | |
| T2 | **학생 크롬북**에서 1단계 [연결 확인] | 성공 | |
| T3 | 선생님 계정으로 로그인 | 로그인 후 내 이메일, 연결 학번 없음 표시 | |
| T4 | **학생 계정**으로 로그인 | 로그인 성공. 실패하면 오류 화면 문구를 그대로 적기 (관리자 제한 여부) | |
| T5 | 학번·이름 연결 / Roster에 없는 학번 입력 | 연결 성공, Bindings 탭에 행 추가 / `NOT_IN_ROSTER` | |
| T6 | HTML 붙여넣기 → 제출 | 버전 1. 드라이브 `vibe-test-submissions/<학번>_v1_<시각>.html` 첫 줄이 `<!-- vibe-submit:학번\|이름 -->`. 아래 명령으로 파싱 확인 | |
| T7 | 다른 계정으로 로그인해 같은 학번 연결 | `ID_BOUND_TO_OTHER` | |
| T8 | 연결하지 않은 계정으로 제출 | `NOT_BOUND` | |
| T9 | 같은 학번으로 다시 제출 | 버전 2, v1 파일은 그대로 남음 | |
| T10 | 2MB 넘는 내용 / `<`로 시작하지 않는 글 | `TOO_LARGE` / `NOT_HTML` (페이지가 먼저 막으면 그것도 정상) | |
| T11 | 부하 시험: 연결 30건 동시, 제출 30건(0~5초 분산) | 모두 성공 또는 재시도 후 성공. 평균·최대 응답 시간 기록 | |
| T12 | 로그인 후 1시간 넘게 두었다가 제출 (토큰 만료) | 자동으로 새 토큰 받아 재시도. 안 되면 "다시 로그인" 안내 | |
| T13 | Config `session_open`을 `FALSE`로 바꾸고 제출 | `SESSION_CLOSED` | |

T6 마커 확인 (드라이브에서 파일을 내려받은 뒤, 저장소 폴더에서):

```powershell
python -c "import sys; sys.path.insert(0,'tools'); import common as C; print(C.split_marker(open(sys.argv[1],encoding='utf-8').read())[:2])" 내려받은파일.html
```

`('31640', '시험용')`처럼 학번과 이름이 나오면 성공입니다.

T11 참고: 부하 시험 칸은 학생에게 보이지 않습니다. 주소 끝에 `#teacher`를 붙여 열면(예: `…/lab/#teacher`) 나타납니다. 한 번에 최대 50건입니다. 제출 부하 시험 전에 Config `submit_per_minute`를 `50`으로 올리세요(안 올리면 6번째부터 `BUSY`). 제출 부하 시험은 드라이브에 파일을 30개 만듭니다. 선생님 시험용 학번으로 연결한 상태에서만 하고, 끝나면 폴더의 시험 파일과 Submissions 행을 지우세요.

## 6. 막혔을 때의 대체안

학생 계정의 구글 로그인이 학교 관리자 설정으로 막히면(T4 실패), 로그인 없이 **반별 입장 코드**로 갑니다. 선생님이 반마다 짧은 코드를 정해 수업 시간에만 알려 주고, 서버는 코드가 맞는 요청만 받습니다. 대신 남의 학번으로 내는 것을 막을 수 없으므로 덮어쓰지 않고 **모든 제출을 시각과 함께 쌓아 두고**(이 시험의 append-only 방식 그대로), 문제가 생기면 선생님이 로그를 보고 판단합니다. 관리자에게 "Google로 로그인" 허용(18세 미만 사용자의 타사 앱 접근 설정에서 이 클라이언트 ID를 신뢰 앱으로 추가)을 요청하는 방법도 함께 시도할 수 있습니다.

## 7. 시험이 끝나면

- `site/lab/` 폴더를 지우고 push → Pages에서 내려갑니다.
- 웹앱: **배포 → 배포 관리 → 보관처리**(archive)로 주소를 끕니다.
- 시트의 `Bindings`(학생 이메일이 들어 있음)는 공유하지 말고, 시험 뒤 지웁니다.

## 기존 설계와 달라지는 점 (본 구현 때 반영할 것)

- 제출 표식(`vibe-submit`)을 학생 브라우저가 아니라 **서버가** 붙입니다. 학생이 붙여넣은 HTML 맨 앞의 `vibe-submit` 줄은 지우고, 연결된 학번·이름으로 새로 씁니다. `vibe-info` 줄은 그대로 둡니다.
- 이름의 `>`도 지웁니다 (`tools/common.py`의 표식 정규식이 이름에 `>`를 허용하지 않음).
- 오류 코드에 `SERVER_ERROR`(예상하지 못한 서버 오류)가 추가되었습니다.
- 제출 크기 상한 기본값이 2MB라서 SPEC의 1MB 상한과 다릅니다. 본 구현 때 1MB로 맞출지 정해야 합니다.
